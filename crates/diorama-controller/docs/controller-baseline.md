# Kubernetes Controller Manager Baseline & Supervision Architecture

## 1. Upstream Kubernetes Baseline

diorama retains its Rust controller manager and its Kubernetes **v1.35.7**
configuration and identity contracts. The upstream executable in the runtime is
kube-scheduler; the controller manager runs in process. The following generated
configuration flags describe its compatibility surface:

- **Secure Port & Binding**:
  - `--bind-address=0.0.0.0` (or `127.0.0.1` in loopback / single-node mode)
  - `--secure-port=10257` (default Kubernetes controller-manager secure port)
- **Authentication & Kubeconfig**:
  - `--kubeconfig`: Points to `kube-controller-manager.kubeconfig` generated by `diorama-pki`
  - Client certificate common name: `system:kube-controller-manager`
  - Authenticated RBAC authorization: Bound to bootstrap `system:kube-controller-manager` ClusterRole and ClusterRoleBinding with full cluster reconciliation authority
  - `--authentication-kubeconfig` and `--authorization-kubeconfig`
- **Service Account Credentials**:
  - `--service-account-private-key-file`: RSA private key (`service-account.key`) used by token-controller to sign service account tokens
  - `--root-ca-file`: Cluster CA certificate (`ca.crt`) injected into service account secrets
  - `--use-service-account-credentials=true`: Individual controllers authenticate using dedicated per-controller service account tokens
- **EndpointSlice Latency & Upstream Defaults (PR #111 / KS-29)**:
  - `--endpointslice-updates-batch-period=0s`: Immediate propagation of service backend changes without historical multi-second delays
  - `--endpoint-updates-batch-period=0s`
  - `--concurrent-endpoint-syncs=5`

## 2. Controller Selection & Historical Allowlist Resolution

### Tracking Upstream Commits
Historical KubeSolo and edge forks introduced brittle controller allowlists that inadvertently dropped required controllers:
- **`f4f5ee9` (upstream PR #40)**: Fixed missing `job` and `cronjob` controllers.
- **`ec05c2c` (upstream PR #68)**: Fixed missing `garbagecollector` controller.
- **`790b2b0` (upstream PR #111 / KS-29)**: Reverted non-standard EndpointSlice batch periods back to standard `0s` defaults.
- **`35d1093` (upstream PR #166 / KS-68)**: Removed edge memory overrides, restoring official Kubernetes reconciliation defaults.

### Controller Enforcement in diorama
In diorama:
1. **Default Controller Set**: Defaults to `["*"]`, enabling all official upstream Kubernetes v1.35.7 controllers.
2. **Anti-Omission Validation**: If an explicit controller list is specified, `ControllerManagerConfig::validate_controllers()` enforces that no critical controller is omitted or explicitly disabled with `-`. The required set includes:
   - `job`
   - `cronjob`
   - `garbagecollector`
   - `endpointslice`
   - `endpoints`
   - `deployment`
   - `replicaset`
   - `statefulset`
   - `daemonset`
   - `podgc`
   - `namespace`
   - `serviceaccount`
   - `serviceaccount-token`
   - `resourcequota`
   - `ttl-after-finished`
   Attempting to configure an allowlist that omits or disables any of these returns `ControllerError::OmittedRequiredController`.

## 3. Supervision & Lifecycle Integration

The controller manager component is managed by `diorama-supervisor` through `ControllerManagerAdapter`:

- **Component Spec**:
  - `id`: `"controller-manager"`
  - `prerequisites`: `["apiserver"]` (API server must be ready before controller manager starts)
  - `kind`: `ComponentKind::LongRunning`
  - `failure_policy`: `FailurePolicy::Fatal`
  - `startup_timeout`: 1 minute
- **Lifecycle Phases**:
  1. **Prerequisite Check**: Validates file existence and user identity in `kube-controller-manager.kubeconfig`, cluster trust in `ca.crt`, and signing key in `service-account.key`. Validates controller list and batch periods. Verifies authenticated API server communication.
  2. **Start**: Initializes the service lifecycle state and verifies supervised readiness.
  3. **Readiness Check**: Confirms ongoing authenticated API connectivity and reports configured controller status. Signals readiness via `context.ready()`.
  4. **Supervised Shutdown**: Listens on `context.changed()` for `StopPhase::Graceful` or `StopPhase::Force`, shutting down the service cleanly.

## Independent workers and scheduling

The controller manager acquires and renews a `kube-controller-manager` Lease before
reconciliation. This prevents competing reconcilers from acting concurrently in
the tested lease contract; it does not establish control-plane HA, and the datastore
continues to require one exclusive owner.

Pods remain unbound until upstream kube-scheduler uses the binding endpoint.
DaemonSet Pods receive required node affinity for an actual registered node;
there is no fallback Node or direct `nodeName` assignment. NodeSetter's Pod, PVC,
and Job placement mutations are removed. Its retained Service mutation concerns
load-balancer behavior only.

The bootstrap controller rejects invalid signer names, CSR signatures, identities,
groups, or usages. It signs valid bootstrap requests only while their token remains
valid and the node name is not already registered. An authenticated node can renew
only its own identity. Approved certificates have a bounded lifetime; CA keys stay
in control-plane PKI. Expired bootstrap-token Secrets are removed with revision
checks. See [joining](../../../README.md#join-workers).
